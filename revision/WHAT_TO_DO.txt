JHS REVISION - NEW ANALYSES FOR REVIEWER 1
==========================================

What this folder does
---------------------
It runs every new analysis the referee asked for (comments 2, 3, 4, 5, 6 and
minor comment 4) on top of your existing pipeline, WITHOUT editing your .qmd
and WITHOUT re-running the hours-long model chunks.

It uses {targets}: results are cached, so when you change one setting only
that analysis is re-run. Editing figures or prose in the main .qmd re-runs
nothing; only a change to the `cfg` or `clean` chunks rebuilds the panel.


STEP 1 - Put the folder in place (2 minutes)
--------------------------------------------
1. Copy this whole folder into your pipeline repository, next to the main
   .qmd, and name it `revision`:

       your-repo/
         no-universal-ranking.qmd      <- (or whatever your main file is called)
         data/...
         revision/                     <- this folder
           _targets.R
           run_without_targets.R
           R/
           WHAT_TO_DO.txt

2. If your main .qmd is NOT called `no-universal-ranking.qmd`, open
   `_targets.R` and change this line:

       MAIN_QMD <- Sys.getenv("MAIN_QMD", "../no-universal-ranking.qmd")

3. Add `revision/_targets/` to your .gitignore. That cache contains a
   respondent-level frame derived from the licensed Gallup data and must
   never be committed or shared.

Requirements: your main .qmd must have chunks labelled `cfg` and `clean`
(a `preflight` chunk is run too if it exists), and the `clean` chunk must
contain the line `rm(DT)`. The folder inserts its own hook just before that
line, in memory only; your file is never modified.


STEP 2 - Install {targets} once (1 minute)
------------------------------------------
In R:
    install.packages(c("targets", "lmerTest"))

(lmerTest gives Satterthwaite p-values; without it the code falls back to
normal-approximation p-values.)


STEP 3 - Check that CFG$QUICK = FALSE in your main .qmd
-------------------------------------------------------
The analyses must run on the full sample, exactly like the published results.


STEP 4 - Run it (about 1-2 hours the first time)
------------------------------------------------
Open R with the working directory set to the `revision` folder, then:

    targets::tar_make()

What happens:
  - `cfg` and `clean` of your main .qmd run once (loading the parquet takes
    the longest part of the setup);
  - blocks R0-R8 run; R7 (prediction) is the slowest.

To see progress in another R session:   targets::tar_progress()
To see the dependency graph:             targets::tar_visnetwork()

If {targets} gives you any trouble, the same analyses run top to bottom with:
    source("run_without_targets.R")
(no caching: it always re-runs everything).

If R7 is too slow or runs out of memory: in R/settings.R set
    n_max = 1e6
inside SET_R7 and run tar_make() again (only R7 re-runs). All feature sets
share the same subsample, so the comparison stays fair.


STEP 5 - Check one number before anything else
----------------------------------------------
Open  <your outdir>/revision/REVISION_SENTENCES.md  and read the R0 sentence.
It compares the country-year baseline used for the robustness checks with
your published coefficients (T03_main_coefficients.csv). If it says
"[CHECK: agreement below .90]", stop and send me
R0_agreement_with_published.csv before using anything else.


STEP 6 - Send me the results
----------------------------
Send the folder  <your outdir>/revision/  (the CSV files and
REVISION_SENTENCES.md). Do NOT send the `_targets/` cache. The CSVs contain
only coefficients and country-year aggregates, no microdata.


WHAT EACH OUTPUT ANSWERS
------------------------
R0  Baseline on the country-year panel and agreement with the published
    model. Every robustness table compares against THIS baseline, on the
    same frame, so changes are never model-vs-different-model.
      R0_baseline_collapsed_cre.csv, R0_agreement_with_published.csv

R1  Comment 3: share of genuinely observed country-years and countries per
    predictor; intermittent fill vs never-fielded.
      R1_coverage_audit.csv

R2  Comment 3: each predictor re-estimated on its observed country-years
    only. Two scales: the published one, and per SD of the observed
    within-deviations (removes the attenuation the referee worries about).
      R2_observed_only.csv

R3  Comment 3: stricter coverage (>=25% / >=50% of country-years observed;
    >=60 / >=100 countries). Which findings keep sign and significance.
      R3_coverage_thresholds.csv, R3_summary.csv

R4  Minor comment 4: within-SD screen at .03 .04 .05 .06 .075 .10, including
    the items that enter below .05.
      R4_within_sd_threshold.csv, R4_summary.csv, R4_items_near_threshold.csv

R5  Comment 4: country-specific linear trends; first differences
    (consecutive waves, and all gaps); placebo leads (next-wave predictor
    should not predict current life evaluation); plus your existing AIC
    lead/lag table T10 that the referee asked to see.
      R5_trends_fd_leads_long.csv, R5_trends_fd_wide.csv, R5_T10_lead_lag_AIC.csv

R6  Comment 5: (a) all perceptual predictors removed; (b) response style:
    Cantril heaping (share at 0 or 10) and a balanced yes-rate
    (acquiescence: saying Yes regardless of the question), described by
    region, used as controls, and countries with extreme styles excluded.
      R6a_perceptual_excluded.csv, R6b_*.csv

R7  Comment 6: same learner, same splits, different predictors: GDP only;
    country means only; within only; pooled undecomposed; full CRE.
    R2 at respondent level (as in the paper) and at country-year level.
      R7_predictive_baselines_summary.csv, R7_predictive_baselines_all_reps.csv

R8  Comment 2: the same panel and predictors under the conventional
    specifications the referee names - pooled OLS with year effects,
    random effects without Mundlak means, two-way country fixed effects -
    side by side with the CRE within and between coefficients.
      R8_conventional_vs_cre_long.csv, R8_conventional_vs_cre_wide.csv

REVISION_SENTENCES.md  One generated sentence per block with the numbers
    filled in. These go into the response letter; never retype numbers.


CHANGING SOMETHING LATER
------------------------
All settings are in R/settings.R, one per block:
    SET_ALPHA  FDR level (all blocks)
    SET_R3     coverage thresholds
    SET_R4     within-SD thresholds
    SET_R7     number of holdouts, held-out share, subsample size, elastic net
Change a value, run targets::tar_make(), and only that block re-runs.


TROUBLESHOOTING
---------------
"Could not find chunks labelled `cfg` and `clean`"
    -> your chunk labels differ; tell me their names.
"`rm(DT)` not found in the clean chunk"
    -> the respondent frame is deleted somewhere else; tell me where.
"Pipeline objects missing after `clean`: ..."
    -> your newer pipeline names an object differently; send me the
       message and your current .qmd.
Anything else: send me the full error text and the output of
    targets::tar_meta(fields = error, complete_only = TRUE)
